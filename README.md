# 대출 상환스케줄

## 1. 프로젝트 설명

채용 과제 "문제 1. 대출 상환스케줄"의 풀이입니다. 과제 원문은 [docs/assignment.md](docs/assignment.md)에 있습니다.

대출액, 만기, 금리, 상환방식 네 값을 받아 매월 상환받을 원금과 이자의 목록을 돌려줍니다. 지원하는 상환방식은 두 가지입니다.

- **원리금균등상환** (`EQUAL_PAYMENT`): 매월 내는 금액(원금과 이자의 합)이 같습니다. 갚을수록 남은 원금이 줄어 이자 몫은 줄고 원금 몫은 늘어납니다.
- **만기일시상환** (`BULLET`): 매월 이자만 내다가 마지막 회차에 원금 전액을 갚습니다.

예를 들어 1,200,000원을 연 12%, 3개월로 빌리면 결과는 다음과 같습니다. 월 금리는 12%를 12로 나눈 1%입니다.

| 회차 | 원리금균등상환 원금 | 원리금균등상환 이자 | 만기일시상환 원금 | 만기일시상환 이자 |
| --- | --- | --- | --- | --- |
| 1 | 396,026 | 12,000 | 0 | 12,000 |
| 2 | 399,987 | 8,039 | 0 | 12,000 |
| 3 | 403,987 | 4,039 | 1,200,000 | 12,000 |

## 2. 요구 환경

- **JDK 25**로 컴파일하고 실행합니다. 스프링 같은 프레임워크를 쓰지 않는 순수 자바 프로젝트입니다.
- **Gradle Wrapper**가 저장소에 들어 있어 Gradle을 따로 설치하지 않습니다.
- JDK 25가 없는 PC에서는 Gradle이 JDK 25를 자동으로 내려받습니다. 다만 Gradle 자체를 실행하려면 **JDK 17 이상이 하나는 설치**되어 있어야 하고, 내려받을 때 인터넷 연결이 필요합니다.
- 소스와 빌드의 인코딩은 UTF-8입니다.

## 3. 빌드, 테스트, 실행 명령

| 작업 | macOS / Linux | Windows |
| --- | --- | --- |
| 빌드 (컴파일 + 테스트) | `./gradlew build` | `.\gradlew.bat build` |
| 테스트 | `./gradlew test` | `.\gradlew.bat test` |
| 실행 | `./gradlew -q run --args="1200000 3 12 EQUAL_PAYMENT"` | `.\gradlew.bat -q run --args="1200000 3 12 EQUAL_PAYMENT"` |

실행 인자는 대출액, 만기, 금리, 상환방식 순서입니다. 위 실행 명령의 출력은 다음과 같습니다.

```
 No.          Principal           Interest
   1            396,026             12,000
   2            399,987              8,039
   3            403,987              4,039
```

코드에서 직접 호출할 때는 값 네 개를 넣으면 목록이 나옵니다. 명령 인자로 실행할 때도 같은 메서드를 호출합니다.

```java
List<Installment> schedule = RepaymentScheduleCalculator.calculate(
        1_200_000L,                    // 대출액 (원)
        3,                             // 만기 (개월)
        new BigDecimal("12"),          // 금리 (연 퍼센트)
        RepaymentType.EQUAL_PAYMENT);  // 상환방식
```

목록의 항목인 `Installment`는 원금(`principal`)과 이자(`interest`) 두 값만 가집니다. 회차는 목록의 순서이고, 합계와 남은 원금은 두 값에서 계산할 수 있습니다.

## 4. 입력값의 형식과 범위, 그렇게 정한 근거

범위를 벗어나거나 형식이 맞지 않는 값은 고쳐서 계산하지 않고 영어 오류 메시지와 함께 거부합니다.

| 입력 | 형식 | 범위 | 근거 |
| --- | --- | --- | --- |
| 대출액 | 원 단위 정수 | 1원 이상 1조 원 이하 | 원화는 1원 미만 단위가 없습니다. 1원만 되어도 계산 규칙이 성립하므로 하한은 1원입니다. 상한은 자릿수 입력 실수를 거르고 검증한 범위를 명시하기 위한 값이며 업계 관례는 아닙니다. |
| 만기 | 개월 단위 정수 | 1개월 이상 600개월 이하 | 과제가 "만기 1개월"을 경계값으로 들었습니다. 600개월은 50년이고, 2023년에 여러 은행이 50년 만기 주택담보대출을 출시했습니다. |
| 금리 | 연 퍼센트 숫자, 소수 셋째 자리까지 | 0% 이상 20% 이하 | 법정 최고금리가 2021년 7월 7일부터 연 20%입니다. 은행연합회의 코픽스 운용 모범규준이 기초 자료의 금리를 소수 셋째 자리까지 다룹니다. |
| 상환방식 | `EQUAL_PAYMENT` 또는 `BULLET` | 대소문자 구분 없음 | 과제가 요구한 두 방식입니다. |

- 금리 `5.2500`처럼 끝에 0이 붙은 표기는 `5.25`와 같은 값이므로 받습니다. `5.2555`는 넷째 자리이므로 거부합니다.
- 금리를 코드에서 넘길 때는 `BigDecimal`을 씁니다. `double`은 5.1 같은 값을 정확히 담지 못해 금액에 오차가 섞이기 때문입니다.

## 5. 과제에 없어서 정한 것과 이유

| 정한 것 | 내용 | 이유 |
| --- | --- | --- |
| 금액 단위 | 원 단위 정수 | 원화 대출이고, 정수로 다루면 소수점 오차가 금액에 섞이지 않습니다. |
| 끝수 처리 | 이자와 월 납입액 모두 원 미만을 버림 | 일부 금융사의 상품 설명서에서 확인된 방식이고, 규칙 하나로 설명됩니다. 모든 금융사의 공통 규정은 아닙니다. |
| 오차 보정 회차 | 마지막 회차의 원금은 그때 남은 원금 전액 | 원금 총합이 대출액과 같다는 구현포인트 1이 계산 구조만으로 보장됩니다. |
| 금리 0% | 허용. 월 납입액은 대출액 나누기 회차 수의 버림 | 과제가 금리 0%를 경계값으로 들었고, 월 납입액 공식은 금리 0%에서 0으로 나누게 됩니다. |
| 원금이 만기 전에 바닥나는 경우 | 월 납입액을 1원 낮춰 처음부터 다시 계산 | 아래 설명을 참고하십시오. |

**원금이 만기 전에 바닥나는 경우**

이자의 원 미만을 버리면 그만큼 원금을 더 갚게 되고, 이 차이가 매월 쌓입니다. 금액이 작고 만기가 길면 마지막 회차 전에 원금을 다 갚아 버려, 그대로 계산하면 음수 금액이 나옵니다.

- 예: 10,000원, 연 5%, 600개월. 공식 값 45.41원을 버린 45원으로 계산하면 597회차에 원금이 바닥납니다.
- 처리: 월 납입액을 44원으로 1원 낮춰 다시 계산합니다. 599회차까지 44원씩 내고, 마지막 회차에 원금 2,533원과 이자 10원을 냅니다.
- 결과: 회차 수가 만기와 같고, 원금 총합이 대출액과 같으며, 마지막 회차를 뺀 합계가 모두 같고, 음수 금액이 없습니다.
- 감수한 점: 마지막 회차가 평소보다 훨씬 커질 수 있습니다. 구현포인트 2가 마지막 회차를 예외로 두었으므로 규칙 위반은 아닙니다.

**계산 정밀도**

- 금리는 0.001퍼센트 단위의 정수로 바꿔 분수로 다룹니다. 연 5.5%의 월 금리는 5,500을 1,200,000으로 나눈 분수입니다.
- 이자는 곱셈을 먼저 하고 정수 나눗셈을 마지막에 한 번만 해서 버림이 한 번만 일어납니다.
- 월 납입액 공식은 `BigInteger` 정수 계산으로 정확히 구한 뒤 한 번만 버립니다. `double`과 `float`는 쓰지 않습니다.

## 6. 구조와 확장 방법

```
org.ruscayn.repayment
├── RepaymentScheduleCalculator  값 네 개를 받아 목록을 돌려주는 진입점
├── Loan                         대출액, 만기, 금리와 범위 검증
├── AnnualInterestRate           금리 검증과 한 달 이자 계산
├── Installment                  한 회차의 원금과 이자
├── RepaymentMethod              상환방식 인터페이스
├── RepaymentType                상환방식을 이름으로 등록한 열거형
├── EqualPaymentMethod           원리금균등상환 (월 납입액 1원 낮추기 포함)
├── EqualPaymentAmortization     주어진 월 납입액으로 만기까지 상환해 보는 계산
├── MonthlyPaymentFormula        월 납입액 공식
├── BulletRepaymentMethod        만기일시상환
└── cli
    ├── RepaymentScheduleApp     main, 사용법과 오류 출력
    ├── LoanArguments            명령 인자 해석
    └── ScheduleTable            표 출력
```

"다양한 상환방식이 추가될 수 있다"는 요구는 `RepaymentMethod` 인터페이스로 반영했습니다. 상환방식마다 클래스를 하나씩 두고, 나머지 코드는 인터페이스만 알고 있습니다.

**새 상환방식을 추가하는 절차** (예: 매월 같은 원금을 갚는 원금균등상환)

1. `RepaymentMethod`를 구현하는 클래스를 만듭니다. `schedule(Loan loan)`에서 회차별 `Installment` 목록을 돌려줍니다.
2. `RepaymentType` 열거형에 한 줄을 추가합니다. 예: `EQUAL_PRINCIPAL(new EqualPrincipalMethod())`
3. 검산한 회차별 금액으로 테스트를 추가합니다.

기존 상환방식의 계산 코드는 고치지 않습니다. 명령 인자의 이름 해석과 사용법 안내는 열거형에서 자동으로 반영됩니다. `RepaymentRuleTest`의 공통 규칙(원금 총합, 회차 수, 음수 없음)은 열거형의 모든 상환방식을 돌며 검사하므로 새 방식에도 바로 적용됩니다.

## 7. 테스트 구성과 근거

테스트는 "이 테스트가 없으면 어떤 실수를 놓치는가"에 답할 수 있는 것만 두었습니다. 현재 89개입니다.

| 종류 | 위치 | 잡는 실수 |
| --- | --- | --- |
| 요건 규칙 | `RepaymentRuleTest` | 11가지 대출 조건에서 원금 총합이 대출액과 다르거나, 회차 수가 만기와 다르거나, 음수가 나오거나, 원리금균등상환의 합계가 달라지는 실수 |
| 검산한 정답 | `EqualPaymentScheduleTest`, `BulletScheduleTest`, `AnnualInterestRateTest` | 규칙은 지키지만 금액이 틀린 계산. 긴 만기에서 월 납입액이 1원 어긋나는 정밀도 실수 |
| 경계값 | `LoanTest`, `AnnualInterestRateTest`, `RepaymentRuleTest` | 각 입력의 최솟값과 최댓값을 거부하거나 바로 바깥 값을 받는 실수. 최소와 최대 조합에서 계산이 깨지는 실수 |
| 계산 방식이 바뀌는 지점 | `EqualPaymentScheduleTest`, `BulletScheduleTest`, `AnnualInterestRateTest`, `RepaymentTypeTest` | 금리 0%, 월 납입액 1원 낮추기, 만기 1개월, 월 납입액 0원처럼 다른 경로를 타는 조건에서의 실수 |
| 잘못된 입력 | `RepaymentScheduleAppTest`, `AnnualInterestRateTest`, `RepaymentTypeTest` | 소수점 대출액, int 범위를 넘는 만기, 숫자가 아닌 금리, 넷째 자리 금리, 모르는 상환방식, 인자 개수 오류를 받아들이는 실수 |
| 표 출력 | `ScheduleTableTest`, `RepaymentScheduleAppTest` | 열 순서나 회차 번호가 틀리는 실수, 종료 코드가 틀리는 실수 |

- "틀렸던 곳" 종류의 테스트는 결함을 고칠 때 추가합니다. 아직 해당하는 결함이 없습니다.
- 테스트와 별도로, 13만 2천 가지 조건(대출액 1원부터 1조 원, 만기 1개월부터 600개월, 금리 0%부터 20%)을 두 상환방식으로 계산해 독립적으로 작성한 계산과 대조했습니다. 26만 4천 개 스케줄에서 규칙 위반과 불일치가 없었습니다.

## 8. 과제 범위를 넘는 추가 스펙과 넣은 이유

| 추가 스펙 | 넣은 이유 |
| --- | --- |
| 명령 인자로 실행해 표로 보여 주는 기능 | 결과를 눈으로 확인하고, README의 명령을 복사해 바로 실행할 수 있게 하기 위해서입니다. 표는 목록에 담긴 원금과 이자, 그리고 순서인 회차만 보여 줍니다. |
| 입력 범위 검증과 오류 메시지 | 자릿수 입력 실수를 거르고, 과제가 요구한 경계값 동작을 분명히 하기 위해서입니다. |
| 상환방식 이름의 대소문자 무시 | 터미널에서 `bullet`처럼 적어도 실행되게 하기 위해서입니다. |
| JDK 25 자동 내려받기 | JDK 25가 설치되지 않은 PC에서도 빌드되게 하기 위해서입니다. |

프로그램이 터미널에 출력하는 글은 영어입니다. 터미널의 인코딩 설정에 따라 한글이 깨질 수 있기 때문입니다.

## 9. 문제 해결

| 증상 | 대처 |
| --- | --- |
| `Cannot find a Java installation ... matching: {languageVersion=25}` | JDK 25 자동 내려받기가 실패한 것입니다. 인터넷 연결을 확인하십시오. 회사 방화벽이 `api.foojay.io`를 막는 환경이면 JDK 25를 직접 설치한 뒤 다시 빌드하십시오. |
| `JAVA_HOME is not set` 또는 `java` 명령을 찾지 못함 | Gradle을 실행할 JDK가 없습니다. JDK 17 이상을 하나 설치하십시오. |
| macOS에서 `./gradlew: Permission denied` | `chmod +x gradlew`를 실행하십시오. |
| 실행 뒤 오류 메시지 아래에 `FAILURE: Build failed with an exception`이 함께 나옴 | 입력이 잘못되어 프로그램이 0이 아닌 종료 코드를 냈고, Gradle이 그것을 실패로 표시한 것입니다. 그 위의 `Error:` 줄이나 `Usage:` 안내를 확인하십시오. |
| Windows PowerShell에서 실행 인자가 나뉘어 전달됨 | `--args="1200000 3 12 BULLET"`처럼 인자 전체를 큰따옴표로 묶으십시오. |

종료 코드는 정상이면 0, 입력값이 잘못되면 1, 인자 개수가 틀리면 2입니다.
