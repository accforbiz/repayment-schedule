## 문제 1. 대출 상환스케줄

코드를 별도 파일로 함께 제출해 주세요. 정확성뿐 아니라 코드 스타일도 평가합니다. 언어 제약은 없습니다.
AI로 작성하셔도 됩니다 — 대신 아래 "함께 제출할 것"을 반드시 채워 주세요.

주식회사 정직기금은 대출자에게 원리금균등상환방식과 만기일시상환방식으로 대출금을 상환받고 있다. 원리금균등상환은 매월 동일한 금액(원금+이자)을 상환하는 방식이고, 만기일시상환은 매월 이자만 상환하다가 마지막 회차에 원금 전액을 상환받는 방식이다. 대출액/만기/금리/상환방식을 입력받아, 매월 상환받을 원금과 이자의 List를 return 하는 코드를 작성하시오. (앞으로 다양한 상환방식이 추가될 수 있다는 비즈니스 조직의 설명이 있었다.)

### 구현포인트

1. return된 원금의 총합은 대출액과 동일해야 한다.
2. 원리금균등상환의 경우, 최소한 첫 회차와 마지막 회차를 제외하고는 원금과 이자의 합이 일치해야 한다. (구현에 따라 첫·마지막 회차 금액도 같을 수 있다.)
3. 실제로는 이자율의 1/365(윤년 1/366)을 매일 처리해야 하나, 문제 편의상 월마다 이자율의 1/12에 해당하는 이자가 발생하는 것으로 한다.
4. 오버스펙으로 구현해도 무방하나, 어떤 이유로 그 스펙을 추가했는지 설명이 필요하다.

### 함께 제출할 것

- AI 대화 로그: 어떤 프롬프트로 코드를 얻었는지 (공유 URL).
- 엣지케이스 검증 노트: AI가 준 코드가 다음을 어떻게 처리하는지 본인 언어로 설명.
  - 반올림 누적오차 → 원금 총합이 대출액과 어긋날 때 어느 회차에서 어떻게 보정하는가 (구현포인트 1)
  - 마지막 회차 잔액 처리
  - 만기/금리/대출액의 경계값(금리 0%, 만기 1개월, 소수점 등) 입력 시 동작
- 확장성 설계 설명: "다양한 상환방식이 추가될 수 있다"는 요구를 코드 구조에 어떻게 반영했는가. (인터뷰에서 새 상환방식 1개를 즉석 추가해 달라고 요청드릴 수 있습니다.)
